## 실제 브라우저 확인 (2026-10-10, 헤드리스 Chrome, 32/32)

## 서버 점검 (2026-10-10)

실제 서버 프로세스와 테스트 클라이언트로 이상한 요청을 대량으로 보내 오류를 찾았습니다(경로×메서드 전수, 본문 퍼징 100여 종, 크기 한계, OpenAI 호출 실패 11종·응답 몸통 10종, 경로 탈출·정보 노출 20여 곳, 보안 헤더, Host 헤더, PDF Range, 동시 접속·메모리).

**찾아서 고친 것**

1. **`/api/convert-backup`이 위장한 뷰를 읽어 서버를 붙잡을 수 있었음(심각)** — 올린 SQLite 파일의 "표"를 무조건 읽었는데, 파일 안에 계산식을 넣은 뷰를 표처럼 꾸미면 4KB 파일로 300만 행을 7.9초 동안 처리했고, 제한 없는 뷰는 끝나지 않거나 메모리를 소진함(로그인 없는 공개 서버). 진짜 표만 허용하고 행 수(시험 2,000·답 12만·메모/해설 840)와 처리 시간(10초) 한도를 둠 → 같은 파일이 0.0초에 거부됨. 수정 전 코드로 새 시험을 돌리면 이 시험이 끝나지 않고 멈춤.
2. 아주 큰 문제 번호(`/question-image/99999999999999999999/…`)가 500 → 404
3. OpenAI 연결 중 응답이 끊기는 오류(`IncompleteRead`·`BadStatusLine`)를 처리하지 않아 500 → 502 "AI 서버에 연결하지 못했습니다"
4. OpenAI 응답 모양이 이상할 때(`[]`·`null`·빈 내용 등 6종) 500 → 502
5. 규칙상 허용되는 긴 AI 대화(12개 × 한글 12,000자, 약 430KB)가 본문 한도 100KB에 걸려 영어 오류로 거부 → 한도를 1MB로 올림, 초과 시 한글 안내
6. 오류 문구가 영어("The data value transmitted exceeds…") → 한글로, 예상 밖 오류는 서버 내부 정보 없이 한글 JSON 500

**문제없음으로 확인한 것**: 모든 경로 × 7개 메서드에서 서버 오류 없음, 경로 탈출·소스·DB·`.git` 노출 없음(`/static/../app.py` 등), 모든 응답에 보안 헤더(CSP·nosniff·X-Frame-Options·Referrer-Policy), PDF Range 요청 206, Host 헤더 검증(`evil.example`·`localhost@evil.example` 등 거부), 이미지 60장 동시(30) 요청 2.2초·실패 0, 이미지 500장 반복 렌더링 후 메모리 75→88MB로 안정, 운영 로그에 서버 오류 없음.

**알려진 한계(고치지 않음)**: 로그인·요청 횟수 제한이 없어 누구나 AI 연결 확인(`/api/ai/settings`)을 통해 이 서버로 OpenAI 키를 시험해 볼 수 있음(서버는 키를 저장하지 않음), 이미지는 요청마다 새로 렌더링(브라우저가 하루 보관), `Host: LOCALHOST`(대문자)는 400(브라우저는 소문자로 보냄), 서버 시작 때 `fitz` 사용 중단 경고.
