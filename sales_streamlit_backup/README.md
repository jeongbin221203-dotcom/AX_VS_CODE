# 영업관리 시스템 (Enterprise Edition) — Streamlit + SQLite

거래처·파이프라인·영업활동·매출을 관리하는 데서 그치지 않고, 대기업·중견기업 영업조직이 실제로 돌리는
**권한 분리 / 예측 관리 / 결재 통제 / 감사 추적**까지 담은 경량 CRM. 외부 DB 서버 없이 파일 하나(`sales.db`)로 동작한다.

## 1. 실행

```bash
pip install -r requirements.txt
streamlit run app.py          # http://localhost:8501
```
Windows는 `run.bat`, macOS/Linux는 `./run.sh`.

첫 실행 시 로그인 화면에서 **샘플 조직·계정 생성**을 누르면 영업본부/영업1·2팀과 역할별 계정 8개가 만들어진다.
기능을 둘러보려면 로그인 후 **⚙️ 데이터 관리 → 샘플 데이터 생성**으로 데모 데이터를 넣는다.

시연용 계정: `정임원`(임원, 전사) / `한팀장`(팀장, 영업1팀) / `김영업`(사원) / `시스템관리자`(관리자)

## 2. 파일 구성

| 파일 | 역할 |
|---|---|
| `app.py` | 화면 12개 메뉴. 역할에 따라 메뉴가 자동으로 줄어든다 |
| `sales_db.py` | 스키마·마이그레이션·CRUD·집계, 접근범위 강제, 감사로그, Stage Gate |
| `enterprise.py` | 조직/권한, 결재, 예측·스냅샷, 전환율·속도, Win/Loss, 채권·여신 |
| `auth.py` | 로그인 게이트. 인증 방식 교체는 이 파일만 수정 |
| `dataio.py` | 일괄 등록(양식·검증·권한확인)과 조건별 추출(엑셀 다중시트·CSV) |
| `sales.db` | SQLite 데이터 (자동 생성·자동 업그레이드) |

## 3. 대기업·중견기업 운영 방식으로 들어간 것

### 3.1 권한과 조직 (RBAC)
본부–팀–사원 계층을 만들고 역할별로 **보이는 데이터 자체를 제한**한다. 화면만 감추는 방식이 아니라
모든 조회 쿼리에 접근범위 조건이 자동으로 붙는다(`ContextVar` 기반이라 세션끼리 섞이지 않는다).

| 역할 | 데이터 범위 | 권한 |
|---|---|---|
| 영업사원 REP | 본인 담당 건만 | 등록·수정, 할인 결재 요청 |
| 팀장 MANAGER | 본인 팀 + 하위 조직 | 팀 예측·실적, 10% 이하 할인 결재 |
| 임원 EXEC | 전사 | 전사 예측·분석, 20% 이하 결재 |
| 관리자 ADMIN | 전사 | 조직·계정 관리, 감사로그, 전체 결재 |

### 3.2 영업 프로세스 통제
- **MEDDIC 자격검증** — 정량효과·결정권자·평가기준·구매프로세스·핵심문제·내부지지자 6개 항목을 체크하고 점수화.
- **Stage Gate** — 단계별 필수 조건 미충족 시 진행을 차단한다. 예: 협상 단계는 MEDDIC 5개 + 금액 + 마감일,
  수주는 6개 전부 + 할인 승인 완료. "말로만 협상 중"인 파이프라인 부풀리기를 구조적으로 막는다.
- **할인 결재(Deal Desk)** — 할인율 10%/20% 구간별로 결재선이 달라지고, **자기 요청 건은 자기가 결재할 수 없다.**
- **감사로그** — 등록·수정·삭제·단계변경·승인·로그인까지 누가 언제 무엇을 했는지 전부 기록.

### 3.3 매출예측 (Forecast)
- **Commit / Best Case / Pipeline / Omitted** 4단계 예측구분. 예측 책임은 Commit 에만 진다.
- **주간 스냅샷** — 주 1회 파이프라인을 얼려 저장하고, 월중 어느 시점에 예측이 흔들렸는지 추적한다.
- **예측 정확도** — 월초 Commit 대비 실제 매출. 80~120%가 정상이며, 120% 초과는 과소예측(사고 은폐),
  80% 미만은 과대예측(파이프라인 부풀리기)으로 본다.
- **파이프라인 커버리지** — 남은 목표 대비 파이프라인 배수. 3배 미만이면 이번 달이 아니라 다음 달이 위험하다는 신호다.

### 3.4 파이프라인 분석
- **단계 전환율 / 평균 체류일** — 단계 이력 테이블에서 산출한다. 어느 구간에서 딜이 죽는지가 숫자로 나온다.
- **Sales Velocity** = (진행 기회수 × 평균 수주금액 × 승률) ÷ 평균 영업주기.
  네 변수 중 무엇을 건드려야 매출이 가장 크게 움직이는지 판단하는 지표.
- **Win/Loss** — 실주사유 분포, 경쟁사별 승률, 유입경로별 수주금액.

### 3.5 채권·여신
결제조건(일)으로 결제기일을 자동 계산하고 **정상/30·60·90일 초과**로 aging 분류. 부분입금을 지원하며
거래처별 **여신한도 소진율**과 한도 초과를 경고한다.

### 3.6 데이터 일괄 등록 · 추출 (📥 메뉴)
**등록** — 거래처·영업기회·영업활동·매출·목표 5종을 엑셀/CSV로 대량 등록한다.
항목별 업로드 양식(예시 행 포함)을 내려받아 채우면 되고, 업로드 즉시 **검증 결과를 먼저** 보여 준다.
오류는 "엑셀 몇 행, 무슨 사유"로 나오며 목록을 CSV로 받아 그대로 수정할 수 있다.

- 날짜는 `2026-01-05` / `2026.1.5` / `20260105` / 엑셀 날짜셀을 모두 인식
- 금액은 `1,000,000` / `3억` / `1억2천만` 표기 지원
- 거래처 중복 시 **건너뛰기 / 덮어쓰기** 선택
- 본인 권한 범위 밖 담당자로는 등록 불가 (업로드를 통한 권한 우회 차단)
- 영업기회 일괄 등록은 이관 데이터로 보아 Stage Gate 를 적용하지 않으며, 건수가 감사로그에 남는다

**추출** — 기간·담당자·단계·기준월로 조건을 걸어 필요한 항목만 뽑는다.
추출 범위는 로그인 사용자의 권한을 그대로 따른다(사원은 본인 데이터만 나온다).

- 프리셋: 월간 실적 보고 / 파이프라인 리뷰 / 채권 현황 / 내부통제 점검 / 전체 백업
- 엑셀 다중 시트로 받으면 **추출정보 시트**(추출일시·추출자·조건)가 함께 들어가 감사 근거가 된다
- 헤더 고정·자동 필터·금액 `#,##0` 서식이 적용되어 그대로 보고서에 쓸 수 있다
- 항목별 개별 CSV 다운로드도 지원(UTF-8 BOM, 한글 Windows 엑셀에서 바로 열림)

## 4. 운영 시 설정

**예측 스냅샷 자동화** — 주 1회 실행을 권장한다(Windows 작업 스케줄러 / cron).
```bash
python -c "import sales_db,enterprise,datetime; sales_db.init_db(); enterprise.take_snapshot(datetime.date.today().strftime('%Y-%m'))"
```

**인증 방식 교체** — `auth.py` 의 `AUTH_MODE` 만 바꾸면 된다. 화면 코드는 수정 불필요.
```bash
set SALES_AUTH_MODE=password   # 사번+비밀번호 (PBKDF2 해시, users.pw_hash)
set SALES_AUTH_MODE=sso        # 리버스 프록시/SSO 가 넘겨준 사용자 이름을 신뢰
```

**DB 위치 변경** — 공유 폴더·NAS 에 두면 팀이 같은 데이터를 본다.
```bash
set SALES_DB_PATH=\\nas\sales\sales.db      # Windows
export SALES_DB_PATH=/data/sales/sales.db   # macOS/Linux
```

**업무 용어 변경** — `sales_db.py` 상단 상수(`STAGES`, `STAGE_PROB`, `STAGE_REQUIREMENTS`,
`DISCOUNT_POLICY`, `MEDDIC_FIELDS`, `LOST_REASONS`)만 바꾸면 전 화면에 반영된다.
할인 결재선을 바꾸려면 `DISCOUNT_POLICY = [(0.0, None), (10.0, "MANAGER"), (20.0, "EXEC"), (100.0, "ADMIN")]`
의 구간값을 조정한다.

## 5. 한계와 확장 지점

- **동시 사용**: WAL 모드로 소규모~중간 규모(수십 명) 동시 조회·입력은 문제없다. 그 이상이면
  `sales_db.py` 의 커넥션 계층만 PostgreSQL 로 교체한다(`strftime` → `to_char` 정도의 수정).
- **인증 강도**: 기본은 간편 선택 방식이므로 사내망 밖에 노출하지 말 것. 외부 공개 시 SSO 또는 password 모드 + HTTPS 필수.
- **감사로그 보존**: 같은 DB 파일에 쌓인다. 보존연한 정책이 있다면 월 단위로 별도 파일에 아카이브하는 배치를 권장한다.
- **백업**: `sales.db` 파일 복사 또는 데이터 관리 메뉴의 엑셀 내보내기.

## 6. 검증 내역

- **기존 DB 무손실 업그레이드**: 구버전 스키마 DB를 열어 건수 변동 0, 신규 컬럼 기본값 보정, `init_db()` 재실행 멱등성 확인.
- **권한 격리**: 사원 7건 < 팀장 33건 < 임원 55건으로 조회 범위가 분리되고, 타팀 데이터가 노출되지 않음을 검증.
- **통제 로직**: MEDDIC 미충족 단계 진행 차단, 할인 승인 없는 수주 차단, 권한 미달 결재 차단, 자기결재 금지 모두 테스트 통과.
- **지표 정확성**: 예측 정확도 89~99%, 전환율·체류일·영업주기·AR aging 이 실제 데이터 기준으로 계산됨을 확인.
- **화면**: 4개 역할 × 전 메뉴를 샘플 데이터·빈 DB 양쪽에서, Streamlit 1.32 / 1.36 / 1.52 세 버전으로 렌더링 검증.
- **등록·추출**: 정상/오류 혼재 CSV, 엑셀 업로드, 깨진 파일, CP949 인코딩, 한글 금액('3억'), 중복 건너뛰기·덮어쓰기,
  권한 범위 밖 담당자 차단, 엑셀 서식(헤더고정·필터·금액서식) 및 추출 시 권한 범위 적용까지 테스트 통과.
- **모듈 정합성**: 서버를 켜 둔 채 파일을 교체했을 때 발생하는 구모듈 혼재 상황을 기동 시 감지해 재시작을 안내.
